Axiōma {{ .Chart.AppVersion }} is installing as {{ .Release.Name }} in {{ .Release.Namespace }}.

Watch it come up:

  kubectl -n {{ .Release.Namespace }} get pods -w

The migration Job runs first; every API pod waits in an init container until the
database carries the migrations its own image expects, so API pods staying in
Init is the expected state until the Job completes.

  kubectl -n {{ .Release.Namespace }} logs job/{{ printf "%s-migrate-%d" (include "axioma.fullname" .) (.Release.Revision | int) | trunc 63 | trimSuffix "-" }}

The gRPC gateway uses a self-signed certificate generated by this chart. Give it
to anything that dials the gateway:

  kubectl -n {{ .Release.Namespace }} get secret {{ include "axioma.api.grpcTlsSecretName" . }} -o jsonpath='{.data.tls\.crt}' | base64 -d

It is valid for these names only; a client dialling any other name fails the
handshake, and adding one means api.grpc.tls.extraSans and a new certificate:

  {{ include "axioma.api.grpcTlsSans" . | fromYamlArray | join ", " }}
{{- end }}

{{- if gt (int .Values.api.replicaCount) 1 }}

WARNING — api.replicaCount is {{ .Values.api.replicaCount }}, and agent dispatch will not work
reliably. Axel holds one gRPC stream to one API pod, and the check that gates
auto-dispatch is in-process state: a ticket created on any other pod returns 200
and starts no run, silently. Set api.replicaCount to 1 if runs matter.

Migrations are unaffected — the Job is the only writer. Two other things do not
divide cleanly either: recurrence, knowledge-gap and mail sweeps run in-process
on a timer in every replica with no leader election, and uploaded documents are
written to local disk{{ if not .Values.api.documents.persistence.enabled }}, on a per-pod emptyDir here, so each replica serves a different set{{ end }}.
{{- end }}

{{- if and .Values.agent.enabled .Values.agent.model.reasoningEffort (not (regexMatch "LITELLM_DROP_PARAMS" (toString .Values.agent.extraEnv))) }}

NOTE — agent.model.reasoningEffort is set and LITELLM_DROP_PARAMS is not. Every
model call carries reasoning_effort, and a provider that does not accept it
fails the run on its first turn. If {{ .Values.agent.model.name }} does not take that
parameter, add LITELLM_DROP_PARAMS to agent.extraEnv — see deploy/README.md.
{{- end }}
